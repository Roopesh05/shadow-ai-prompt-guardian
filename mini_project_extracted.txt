=== SLIDE 2 ===
Problem Statement
The increasing use of public AI chatbots creates a risk of accidentally sharing 
sensitive information. Users may unknowingly paste API keys, passwords, personal 
data, source code, or confidential business information into AI prompts. Once the 
prompt is submitted, this information may be transmitted to an external AI service. 
Traditional DLP solutions may require additional network infrastructure or 
centralized monitoring. Therefore, a lightweight client-side solution is needed to 
detect and prevent sensitive data leakage before the prompt is transmitted.


=== SLIDE 3 ===
Abstract
• SENTINEL is a client-side Data Loss Prevention (DLP) browser extension. 
• It protects sensitive information entered into public AI chatbots. 
• It prevents accidental sharing of credentials, PII, source code and confidential data. 
• It works directly inside the browser before information is transmitted. 
• It supports browser-based AI platforms such as ChatGPT, Claude and Gemini.
• SENTINEL uses a multi-layer detection engine to identify sensitive information
• More than 150 signature patterns are used to detect known sensitive data. 
• Shannon Entropy is used to identify possible unknown secrets.


=== SLIDE 4 ===
Abstract
• The Luhn Algorithm is used to validate payment-card candidates. 
• PII, passwords, credentials and confidential information are detected locally. 
• Text normalization helps detect simple obfuscation techniques.
• High-risk prompts can be blocked before they are transmitted. 
• Explainable warnings show users why their prompt was flagged. 
• Auto-Redaction replaces sensitive values with safe placeholders. 
• Masked security events are stored locally using SHA-256 hash chaining. 
• Prompt data and telemetry are not sent to external servers. 
• SENTINEL provides a lightweight and privacy-focused approach to AI data 
protection.


=== SLIDE 5 ===
Objectives
• To detect sensitive information in AI prompts before it is transmitted to external AI 
services. 
• To monitor user inputs and provide real-time security warnings. 
• To identify API keys, passwords, PII, payment-card data and other confidential 
information. 
• To calculate a risk score and classify detected information based on severity. 
• To block high-risk prompts and prevent accidental data leakage. 
• To provide automatic redaction so users can safely submit sanitized prompts.


=== SLIDE 6 ===
Literature Survey & Gaps
Literature Survey
• Traditional Data Loss Prevention (DLP) systems mainly use network monitoring, 
proxy servers and centralized security controls. 
• Existing security approaches focus on preventing sensitive data from leaving 
organizational systems. 
• AI chatbots introduce a new data-leakage risk because users directly enter 
information into external AI platforms. 
• Existing solutions may not provide real-time, prompt-level protection directly 
inside the browser. 
• There is a need for a lightweight solution specifically designed to inspect AI 
prompts before transmission.


=== SLIDE 7 ===
Research Gaps
• Limited client-side protection specifically focused on AI chatbot prompts. 
• Lack of immediate detection and blocking before sensitive data is transmitted. 
• Limited user-friendly explanations about why a prompt is flagged. 
• Lack of simple automatic redaction for detected sensitive information. 
• Need for a privacy-focused approach that performs detection locally without 
sending prompt data to external servers.

=== SLIDE 8 ===
Existing Solutions & Limitations
Existing Solutions
• Traditional DLP Systems: Monitor and control sensitive data moving through 
organizational networks. 
• Network Proxies: Inspect network traffic and apply security policies before data 
reaches external services. 
• Endpoint Security: Monitors user devices and applications to identify potentially 
sensitive activities. 
• Organizational Policies: Depend on user awareness and rules to prevent 
employees from sharing confidential information. 
• AI Usage Controls: Organizations can restrict or monitor access to external AI 
platforms.


=== SLIDE 9 ===
Existing Solutions & Limitations
Limitations
• These solutions may require additional infrastructure and configuration. 
• Manual protection depends heavily on user awareness and careful behavior. 
• Network-level monitoring may not provide direct prompt-level feedback. 
• Users may not know which part of a prompt contains sensitive information. 
• Existing approaches may not provide one-click automatic redaction before 
submission.


=== SLIDE 10 ===
Proposed Solution
• SENTINEL is proposed as a client-side Data Loss Prevention browser extension 
for AI chatbots. 
• It monitors user prompts and detects sensitive information before the request is 
transmitted. 
• The detection engine uses 150+ signatures, Shannon Entropy, Luhn validation 
and PII detection. 
• Detected information is classified according to its type, severity and associated risk 
score. 
• High-risk prompts can be blocked, while sensitive values can be removed using 
Auto-Redaction. 
• The system processes prompts locally and stores only masked audit information 
in browser storage.


=== SLIDE 11 ===
Technology Stack
• HTML5, CSS3 and JavaScript ES6+ are used to develop the browser extension. 
• Chrome Manifest V3 provides the extension architecture and security model. 
• Service Worker handles background processing and extension events. 
• chrome.storage.local stores configuration and masked audit information locally. 
• SHA-256 and Luhn Algorithm are used for audit security and payment-card 
validation. 
• Node.js is used for testing and evaluating the detection system.

Working Methodology
• The user enters or pastes a prompt into a supported AI chatbot. 
• SENTINEL monitors the input and intercepts the request before transmission. 
• The prompt is normalized and analyzed using multiple detection techniques. 
• Detected information is classified based on its type, severity and risk score. 
• The system decides whether to Allow, Block or Redact the prompt. 
• A masked security event is stored locally for auditing.

=== SLIDE 15 ===
Use Case Scenario
• Prompt Entry → Developer pastes authentication code into an AI chatbot for 
debugging.
• Sensitive Data → The code accidentally contains an API key and database 
credentials.
• Detection → SENTINEL scans the prompt and identifies the sensitive information.
• Warning & Block → A risk warning is displayed and the request is blocked if the 
risk is critical.
• Auto-Redaction → Sensitive values are replaced with safe placeholders such as 
[API_KEY].
• Safe Submission → The sanitized prompt is submitted to the AI chatbot without 
exposing the original credentials.


=== SLIDE 16 ===
User Flow
• Open AI Chatbot → User opens a supported AI platform in the browser.
• Enter Prompt → User types or pastes a prompt into the chatbot.
• Monitor & Scan → SENTINEL monitors the input and scans for sensitive 
information.
• Risk Analysis → Detected data is classified and a risk score is calculated.
• Decision → Prompt is Allowed, Blocked or Redacted based on the risk level.
• Continue Safely → User submits the sanitized prompt, while a masked audit 
record is stored locally.


=== SLIDE 17 ===
AI Models Explanation
• Regex Model → Uses predefined patterns to detect known API keys, passwords, 
tokens and sensitive data.
• Shannon Entropy → Measures the randomness of text to identify possible 
unknown secrets.
• Luhn Algorithm → Validates possible payment-card numbers and reduces 
incorrect detections.
• PII Detection → Identifies personal information such as email addresses and 
phone numbers.
• TF-IDF + Logistic Regression → Experimental machine-learning model used to 
classify prompts based on their text features.
• Combined Detection → Multiple techniques work together to improve sensitive-
data detection and risk assessment.


=== SLIDE 18 ===
Innovation
• Pre-Transmission Protection → Detects sensitive information before the 
prompt reaches the external AI service.
• Multi-Layer Detection → Combines 150+ signatures, entropy, Luhn validation

• Privacy-First Processing → Performs prompt analysis locally without sending

• Auto-Redaction → Automatically replaces detected sensitive values with safe

=== SLIDE 19 ===
Data Flow (Technical)
• Prompt Input → User enters or pastes the prompt into the AI chatbot 
interface.
• Content Script → Monitors the webpage, input fields and user interactions.

=== SLIDE 21 ===
Challenges & Solutions
• Dynamic AI Websites → MutationObserver detects changes in webpage elements 
and maintains monitoring.
• React-Controlled Inputs → Native setters and synthetic events help synchronize 
monitored input fields.
• Obfuscated Data → Text normalization handles unusual spacing, invisible 
characters and Unicode variations.
• Encoded Secrets → Base64 content is decoded and scanned again for sensitive 
information.
• False Positives → Entropy thresholds and Luhn validation help improve detection 
accuracy.
• Browser Limitations → The current system focuses on browser-based AI 
platforms rather than terminal applications.
